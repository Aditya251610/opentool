# OpenTool Design Context (v3 — Redesign)

## Design Context

### Users

**Primary audience**: Backend and full-stack developers building AI agents who need tool integrations (GitHub, Slack, Gmail, Notion, etc.) without vendor lock-in. They're evaluating OpenTool against Arcade.dev and Composio — they'll pick the one that looks like it was built by someone who actually ships.

**Context of use**: Developers discover OpenTool from a GitHub README, a tweet, or a search for "open source MCP server." They land on the marketing site to evaluate it, then move to the dashboard to connect tools and manage API keys. They interact with OpenTool primarily through the CLI or SDK — the dashboard is for setup and monitoring.

**Job to be done**: Wire up third-party APIs (GitHub, Slack, Stripe, etc.) as MCP-compatible tools for their AI agents, without writing OAuth flows, token refresh logic, or API wrappers themselves. Self-hosted, own their data, no recurring SaaS bill.

### Brand Personality

**Three words**: Sharp. Owned. Uncompromising.

**Voice**: Direct and technical. No filler, no buzzwords, no "supercharge your workflow." Slightly aggressive when calling out bad patterns — this is the tool senior engineers wish existed. Talks to developers as peers, not prospects.

**Emotional goals** (all four, weighted):

1. **"This is serious infrastructure"** — trust, reliability, production-grade (primary)
2. **"This dev gets it"** — sharp, opinionated, built by someone who felt the pain
3. **"This is beautiful AND works"** — polished craft that signals quality
4. **"Finally, something I can own"** — freedom, self-hosted pride

### Aesthetic Direction — "Cosmos"

**Visual tone**: Deep space, luminous, alive. The interface lives in the void between stars — dark foundations with electric light that feels like energy, not decoration. Think mission control for AI infrastructure, not another dark-mode SaaS.

**Theme**: Dark only. Deep void base (`#030014` — near-black with violet undertone) with space-tinted surfaces (`#0a0a1a`, `#0d0d24`, `#15153a`). Never pure black, never gray — always tinted toward the cosmos.

**Color system**:

- **Brand cyan** `#00d4ff` — primary accent, links, CTAs, interactive elements
- **Brand cyan hover** `#38e0ff` — lighter cyan for hover states
- **Accent violet** `#8b5cf6` — secondary, used in gradients and decorative elements
- **Accent pink** `#ec4899` — tertiary, gradient endpoints, emphasis sparks
- **Text gradient**: `from-[#00d4ff] via-[#8b5cf6] to-[#ec4899]` — the signature OpenTool gradient, used for the "Tool" text in logo, section headlines, CTA text
- **Muted brand** `rgba(0,212,255,0.08)` — subtle tints for backgrounds, borders

**Hero**: Custom WebGL2 GLSL space nebula shader — 6-octave FBM with 3 layers of domain warping, starfield with twinkling, chromatic wisps, mouse-reactive energy bloom. Not Three.js — raw WebGL for performance and control.

**Orbital system**: Framer Motion orbital ring with 8 provider icons circling the hero center. SVG icons counter-rotate to stay upright. Central portal glow with cyan→violet→pink gradient ring. Desktop-only, respects prefers-reduced-motion.

**Logo**: SVG text wordmark — "Open" in white, "Tool" with cyan→violet gradient fill. Brand mark is an orbital ring icon with gradient stroke, glowing core, and 3 orbital nodes. Clean, geometric, not pixel art.

**Motion**: Framer Motion for scroll reveals (FadeIn, StaggerIn components), CSS keyframes for orbiting. Shooting stars easter egg spawns randomly. All animation respects prefers-reduced-motion.

**Component style**: Glass morphism + cosmic surfaces. `.nebula-card` with subtle white borders, translucent backgrounds. `.glass-card` for elevated panels. Borders over shadows, but borders are always semi-transparent white, never colored borders.

**References**:

- Aceternity UI — dark premium, component craft, scroll-driven reveals
- shadcn/ui — composable, minimal chrome, developer-native
- Linear — density, speed, opinionated design
- Cosmos/space themes — but earned through custom shader work, not stock assets

**Anti-references**:

- Generic SaaS with gradient blobs and stock illustrations
- "AI product" aesthetic with purposeless floating particles
- Arcade.dev (respect their craft, but OpenTool has its own identity)
- Any template that could be another product with a logo swap

### Design Principles

1. **Precision over decoration** — Every pixel serves a purpose. The nebula shader conveys "living infrastructure," the orbital ring shows real integrations, the shooting stars reward attention. Nothing is ornamental.

2. **Depth through light, not shadow** — Luminous elements (gradients, glows, shader effects) create depth on the void canvas. The z-axis comes from light intensity, not drop shadows.

3. **Space is alive** — The dark theme isn't cold or sterile. The cosmic palette (cyan, violet, pink) and motion (orbits, stars, shader) make the void feel like it's humming with energy.

4. **Developer-native density** — Tight spacing in data views, generous in marketing. The bento grid is information-dense. The hero breathes. Both are intentional.

5. **Owned, not borrowed** — The custom GLSL shader, the orbital ring, the shooting stars, the gradient system — these are OpenTool's fingerprint. No section could be mistaken for another product.

### Technical Stack

- **Framework**: Next.js 15 + Tailwind CSS + Framer Motion
- **Fonts**: Geist Sans + Geist Mono (loaded via next/font)
- **Icons**: Lucide React + custom SVG brand marks
- **Shader**: Raw WebGL2 (no Three.js dependency for hero)
- **Build**: 17 pages, ~19.7kB landing page, static generation
- **CSS architecture**: globals.css utility classes (`.nebula-card`, `.glass-card`, `.text-gradient`, `.section-nebula`, `.section-cosmos`, `.hero-glow`, `.cta-glow`) + Tailwind for layout/spacing
